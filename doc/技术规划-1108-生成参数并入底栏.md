# 技术规划 · 1108 —— 生成参数并入底栏（模型在前，参数跟随模型）

> 给执行者（Codex）：本文是**可直接执行的需求 + 技术方案**。只改本文列出的范围，不做额外重构。
> 遇到本文没写到的细节，**以参考仓库 demo-canvas 的现有实现为准**；参考仓库里也没有的，选最简单的做法，并在提交说明里写明。

## 0 · 背景：为什么要改

角色 / 服装 / 场景 / 道具的详情弹窗（`src/components/AssetDetail.tsx`）里，生成参数放在两个地方：

- **左栏中部**：`生成比例 / 生成数量 / 图片清晰度` 三个原生 `<select>`（`.paramGrid`，约第 1705–1721 行）
- **通栏底栏最左**：图像模型的原生 `<select>`（`.genFootBar > .footModel`，约第 1974–1980 行）

问题在于：**模型决定了有哪些参数可选、可选值是多少**，但界面上模型放在参数下面。用户先调好参数，再去底栏换模型，上面的参数会跟着变（或者应该变但现在根本不变），用户感知不到。另外：

- 比例、清晰度用的是 `defaultValue` 非受控写法，和模型没有任何关联；
- 三个模型的能力没有任何数据描述，`MODEL_OPTS` 只是三个字符串；
- 价格写死为 `COST_PER_IMAGE`，换模型不影响价格。

**本轮目标**：把「模型 + 参数」合并成底栏左侧的一行（模型在最左，参数紧跟在右边），交互和视觉照搬 demo-canvas 视频面板底栏的那一版；模型能力由数据驱动，换模型时参数自动收敛到合法值，并明确告诉用户哪些值被改了。

## 4 · 技术方案

### 4.1 `src/data/imageModels.ts`（新增）

参数统一用**无空格**的比例写法（`'3:4'`，不是现在代码里的 `'3 : 4'`），`RatioBox` 要靠 `split(':')` 解析。

```ts
import { COST_PER_IMAGE } from './pricing'

export type ImageModelId = 'nano-3-pro' | 'nano-2-pro' | 'seedream-3'
export type Tier = 'free' | 'vip'
export type Resolution = '1K' | '2K' | '4K'
export type ParamKey = 'resolution' | 'ratio' | 'count'

export interface ImageParams { resolution: Resolution; ratio: string; count: number }

export interface ImageModelCap {
  label: string
  vendor: 'phan' | 'seedream'      // 决定徽章里用哪枚图标
  tier: Tier                        // vip 才挂 VIP 胶囊
  isNew?: boolean                   // 最多只给一个模型
  resolutions: Resolution[]         // 按从低到高排列
  ratios: string[]                  // 只有一个值 = 该模型固定这个比例
  counts: number[]                  // 按从小到大排列
  costPerImage: number
}

/** 演示数据。真实能力和价格接后端后从接口获取；数字可以由产品随时调整。 */
export const IMAGE_MODELS: Record<ImageModelId, ImageModelCap> = {
  'nano-3-pro': { label: 'Phan nano Image 3 Pro', vendor: 'phan', tier: 'vip', isNew: true,
    resolutions: ['1K', '2K', '4K'], ratios: ['3:4', '1:1', '9:16', '16:9'], counts: [1, 2, 4, 6], costPerImage: COST_PER_IMAGE },
  'nano-2-pro': { label: 'Phan nano Image 2 Pro', vendor: 'phan', tier: 'free',
    resolutions: ['1K', '2K'], ratios: ['3:4', '1:1', '9:16', '16:9'], counts: [1, 2, 4], costPerImage: 20 },
  'seedream-3': { label: 'Seedream 3.0', vendor: 'seedream', tier: 'free',
    resolutions: ['1K', '2K'], ratios: ['1:1'], counts: [1, 2, 4], costPerImage: 12 },
}
export const IMAGE_MODEL_IDS = Object.keys(IMAGE_MODELS) as ImageModelId[]
export const DEFAULT_IMAGE_MODEL: ImageModelId = 'nano-3-pro'
/** 默认值沿用现状：比例 3:4、数量 4、清晰度 2K */
export const DEFAULT_IMAGE_PARAMS: ImageParams = { resolution: '2K', ratio: '3:4', count: 4 }

export interface ParamChange { key: ParamKey; from: string | number; to: string | number }

/**
 * 换模型时把参数收敛到新模型的合法值域。纯函数。
 * - resolution：值在新模型里有就保留；没有就取「不高于当前值」里最高的一档；都高于当前值时取最低档。
 * - ratio：有就保留；没有时，新模型只有一个比例就用它；否则优先 '1:1'，没有 '1:1' 时取第一个。
 * - count：有就保留；没有就取「不大于当前值」里最大的；都大于当前值时取最小的。
 * 返回新参数，以及发生变化的项（用于提示和高亮）。
 */
export function fitParams(model: ImageModelId, p: ImageParams): { params: ImageParams; changed: ParamChange[] }

/** 模型下拉里每行的说明文字，例如：
 *  「1K/2K/4K · 4 种比例 · 单次最多 6 张 · 30 星钻/张」
 *  「1K/2K · 固定 1:1 · 单次最多 4 张 · 12 星钻/张」 */
export function specLine(cap: ImageModelCap): string

/** 参数只有一个可选值时的置灰原因，有多个可选值时返回 ''。
 *  ratio：`${label} 固定输出 ${ratio}`；resolution：`${label} 仅支持 ${res}`；count：`${label} 每次生成 ${n} 张` */
export function lockedReason(model: ImageModelId, key: ParamKey): string

/** 换模型后的提示文案。changed 为空时返回 ''。
 *  例：「已切换至 Seedream 3.0：清晰度调整为 2K，比例调整为 1:1」 */
export function switchMessage(model: ImageModelId, changed: ParamChange[]): string
```

参数名称统一用：清晰度 / 比例 / 数量。数量的显示值为 `${n} 张`。

### 4.2 `src/components/gen/Overlay.tsx`（精简移植）

从参考仓库的 `src/generator/Overlay.tsx` 移植，**只保留**以下能力，其余属性和分支（`side` / `sideLock` / `onShift` / `tries` / `raf` / `modal` / `center` / `tailNear` / `sideAlign` / `below` / `onMouseEnter` / `onMouseLeave`）全部删除：

- 定位：默认放在锚点**上方**（底栏在弹窗底部），上方放不下时翻到下方；左右按视窗夹紧，左右各留 12px

- `ResizeObserver` 重新定位；`resize`、`scroll`（capture）时重新定位

- `tail` 为 true 时画一个指向锚点的小尖角

`track` 要保留：`useTip` 依赖它在鼠标扫过不同元素时重新定位（参考仓库 `useTip.tsx` 里有注释说明）。

样式写在 `GenSettingsBar.module.css` 里，通过 `className` 传入。因为 portal 出去之后不在弹窗 DOM 树里，样式只能用 module class，不能依赖父级选择器。浮层 `z-index` 要高于 `AssetDetail` 弹窗：先查 `Modal.module.css` 里弹窗的 z-index，再设一个比它大的值。

### 4.6 `src/components/gen/GenSettingsBar.tsx`（新增）

受控组件，不持有业务状态，只持有「哪个下拉开着」。

```ts
interface Props {
  model: ImageModelId
  params: ImageParams
  onModelChange: (m: ImageModelId) => void
  onParamsChange: (p: ImageParams) => void
  flash?: ParamKey[]        // 这些格刚被自动调整过，播放一次高亮
  disabled?: boolean        // 生成中：整排不可点
}
```

结构和行为对齐参考仓库 `VideoSettings.tsx`：

1. **模型按钮** `.mdl`：`ModelRing(d=20)` + 模型名（14px / 500）+ `TierPill` + **`IcChev` 12px（`--text-muted`）**。下拉箭头是参考仓库没有的，本轮新增，让用户知道这里可以点。胶囊形，hover 显示 `--fill` 底，打开时显示 `--fill-2` 底，和参数格之间留 10px 间距。
2. **三个参数格**，顺序固定为：清晰度 → 比例 → 数量。
   - 清晰度：`IcQuality`，`lv` 取值 1K→1、2K→2、4K→3，值显示为 `2K`
   - 比例：`RatioBox`（照搬，长边 15px），值显示为 `3:4`
   - 数量：`IcImage`，值显示为 `4 张`
   - 每格就是参考仓库里的 `Field`：可选值多于一个时点击弹出 `.drop`，选中项后面有 `IcCheck`（`--accent`），比例的选项前面带对应的 `RatioBox`
   - 可选值只有一个时：`aria-disabled="true"`，不弹下拉，用 `useTip` 悬浮显示 `lockedReason(...)`，样式照搬参考仓库的 `.gp-field[aria-disabled=true]`
3. **模型下拉** `.mdlDrop`（宽 340px）：每行 `ModelRing(d=22)` + 名称 + `TierPill` + `NEW` 胶囊 + 行末 `IcCheck`；`specLine` 小字在**悬浮 / 聚焦 / 选中**时才显示，行高固定不跳动。这部分样式照搬参考仓库的 `.mdl-row` 系列。本轮没有不可选的模型，不需要 `modelBlockedReason`。
4. **flash**：`flash` 里包含的格加上 `.flash` class，用 `@keyframes` 做一次 1.2s 的 accent 色背景淡出（`rgba(var(--accent-rgb), .22)` → 透明）；同时值的文字颜色在这段时间里用 `--accent`。
5. `disabled` 为 true 时，模型按钮和参数格都加 `aria-disabled`，不响应点击。
6. 无障碍属性照搬参考仓库：`aria-expanded`、`aria-label`（例如 `清晰度：2K`，置灰时追加原因）、`aria-pressed`。

`GenSettingsBar.module.css`：从参考仓库 `app.css` 的对应段落移植，**连同那些解释设计意图的注释一起移植**，class 改成 camelCase（`.gp-field` → `.field`，`.mdl-row` → `.mdlRow`，以此类推）。
