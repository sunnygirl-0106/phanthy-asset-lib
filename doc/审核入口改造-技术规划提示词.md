## 1. 产品决策（已定，不要发散）

这些是产品已经拍板的，实现时请照做，有疑问先提出来再动手：

1. **一个入口、一个名字**。所有需要「我拍板」的事，都在**审核中心**（`#/review`）。不再按角色改名（现在 admin 叫「广场审核」、主账号叫「审批中心」，统一改成「审核中心」），Tab 内容按角色分流。
2. **admin 看到两个 Tab**：`作品` | `素材`。作品 Tab 在 demo 里只做只读陈列（真实平台已有），素材 Tab 是本次重点。
3. **主账号看到一个 Tab**：`团队沉淀申请`。
4. **子账号看不到这个菜单项**，但**必须能收到通知**——通知铃铛对子账号可见，这是整条链路的闭环前提。
5. **团队资产库只放二级入口**，不放审批 UI。一份审核逻辑只维护一处，二级入口 deep-link 跳 `#/review`。
6. **下架 ≠ 删除**。广场素材加状态位，下架只改状态、不删数据，可以重新上架。
7. **驳回 / 下架理由选填**，提供常用理由快选，理由随通知发给投稿人。
8. **子账号投稿广场直达 admin**，主账号不拦截，但收到一条知会通知。

## 2. 数据模型改动

### 2.1 `src/data/types.ts`

新增一个枚举：

```ts
/**
 * 广场素材的上架状态（本次新增）。只有 scope==='plaza' 的资产才谈得上它。
 *
 * 为什么要有这个：原来 admin「下架」是把资产从 world.assets 里直接删掉，
 * 数据一没，就无从「重新上架」——而审核中心的职责恰恰是「处理下架与重新上架」。
 * 所以下架改成打状态位：数据留着，只是不在货架上陈列。
 */
export type PlazaShelfStatus = 'listed' | 'delisted'
```

`Asset` 接口新增四个可选字段（**都只对 `scope==='plaza'` 有意义**，其它层恒为空）：

```ts
  /** 上架状态。缺省（undefined）一律视为 'listed'——种子里的官方素材不用逐个补字段。 */
  shelfStatus?: PlazaShelfStatus
  /** 下架理由（选填）。随通知发给投稿人，让他知道怎么改。 */
  delistedReason?: string
  /** 下架时间 / 操作人，纯记录，用于审核中心列表上显示「谁在什么时候下的」。 */
  delistedAt?: number
  delistedBy?: string
```

> **实现提示**：全仓库读这个字段时一律用 `(asset.shelfStatus ?? 'listed')`，不要写 `=== 'listed'` 的裸判断，否则种子数据会全部被判成非上架。建议在 `permission.ts` 里导出一个小助手 `isListed(asset)` 统一收口。

`Notification` 接口新增两个可选字段：

```ts
  /**
   * 消息类型（本次新增）。本期只用于前端分类/图标，不参与任何逻辑判断。
   * 加它是因为产品要能一眼说清「平台会发哪几种消息」，字符串文案不适合当契约。
   */
  kind?: NotificationKind
  /** 点这条通知跳去哪（hash 路由串，如 '#/review'）。不填就是不可点。 */
  link?: string
```

配套枚举：

```ts
/**
 * 平台会发出的消息类型。产品口径的四类 + 补齐链路必需的三类。
 *   plaza_approved        投稿通过、已上架素材广场            → 发给投稿人
 *   plaza_rejected        投稿被驳回（带理由）                → 发给投稿人
 *   plaza_delisted        已上架的贡献素材被 admin 下架（带理由）→ 发给投稿人
 *   plaza_relisted        已下架素材被重新上架                → 发给投稿人
 *   deposit_submitted     子账号发起沉淀申请                  → 发给主账号（★原来缺这条）
 *   deposit_approved      沉淀申请通过、已进团队库            → 发给申请人
 *   deposit_rejected      沉淀申请被驳回（带理由）            → 发给申请人
 *   plaza_submit_notice   子账号向广场投了稿（知会，不拦截）  → 发给主账号
 */
export type NotificationKind =
  | 'plaza_approved' | 'plaza_rejected' | 'plaza_delisted' | 'plaza_relisted'
  | 'deposit_submitted' | 'deposit_approved' | 'deposit_rejected'
  | 'plaza_submit_notice'
```

## 3. 权限层改动 · `src/services/permission.ts`

新增三个纯函数，按现有风格写注释：

```ts
/**
 * 一份广场素材现在是不是在货架上。
 * 缺省（老数据 / 种子官方素材没有这个字段）一律算「在架」。
 * 全仓库判断上架状态都走这里，不要在页面里裸写 shelfStatus 比较。
 */
export function isListed(asset: Asset): boolean {
  return (asset.shelfStatus ?? 'listed') === 'listed'
}

/**
 * 谁能把一份已下架的素材「重新上架」：只有 admin。
 * 投稿作者不行——他能撤回自己的稿（删除），但把东西放回全网货架是平台的权力。
 */
export function canRelistPlazaAsset(user: User, asset: Asset): boolean {
  return isAdmin(user) && asset.scope === 'plaza' && !isListed(asset)
}

/**
 * 能不能进「审核中心」这个页面。
 * 收口成一个函数，是为了让菜单项（AvatarMenu）和页面本身用同一个判定，
 * 不会出现「菜单不显示但直接改 hash 能进去」这种不一致。
 */
export function canEnterReviewCenter(user: User): boolean {
  return isAdmin(user) || isOwner(user)
}
```

**修改 `canSee` 的 plaza 分支**（这条很关键，漏了会导致下架的素材还挂在广场上）：

```ts
    case 'plaza':
      // 已下架的素材不再对外陈列：只有 admin（治理）和投稿人本人（能看到自己的稿被下了）看得见。
      if (!isListed(asset)) {
        return isAdmin(user) || (!!asset.contributedBy && asset.contributedBy === user.id)
      }
      return canBrowsePlaza(user)
```

**保留** `canRemovePlazaAsset` 不动，但更新它的注释：它现在的语义收窄为「**作者撤回自己的投稿**」（硬删除）。admin 的下架走新的 `runDelistPlaza`，不再走它。

## 4. 状态层改动 · `src/store/useStore.ts`

### 4.1 拆分 / 新增 action

| Action | 变化 | 说明 |
|---|---|---|
| `runRemovePlaza(assetId)` | **语义收窄** | 只保留「作者撤回自己投的稿」这一条路径：`if (isAdmin(user)) return fail('管理员请用下架，不要直接删除')`。仍然硬删除（作者撤稿就是不要了）。 |
| `runDelistPlaza(assetId, reason?)` | **新增** | admin 下架。**不删数据**，只写 `shelfStatus='delisted'` + `delistedReason` + `delistedAt` + `delistedBy`。给投稿人发 `plaza_delisted` 通知，理由拼进文案。官方素材（无 `contributedBy`）不发通知。 |
| `runRelistPlaza(assetId)` | **新增** | admin 重新上架。写回 `shelfStatus='listed'`，清空 `delistedReason/At/By`。发 `plaza_relisted` 通知。 |
| `approvePlazaSubmission(id)` | **改** | 上架时给新资产写上 `shelfStatus: 'listed'`；给 submission 写上 `resultAssetId`、`reviewedBy`、`reviewedAt`。 |
| `rejectPlazaSubmission(id, reason?)` | **加参数** | 记录 `reason` / `reviewedBy` / `reviewedAt`，理由拼进通知文案。 |
| `rejectApplication(id, reason?)` | **加参数** | 同上。 |
| `approveApplication(id)` | **改** | 记录 `reviewedBy` / `reviewedAt`。 |
| `runDeposit(sourceId)` | **改** | 子账号提交申请那一支，**额外给主账号发一条 `deposit_submitted` 通知**（这是产品列的第 4 类消息，原来只有头像红点，没有通知）。 |
| `runContribute(sourceId)` | **改** | 发起人是子账号时，**额外给其主账号发一条 `plaza_submit_notice` 知会通知**（不拦截，只是让主账号知道团队的东西要外流）。 |

> **接口签名同步**：`StoreState` 里这几个 action 的类型声明要一起改，注释一起更新。

### 4.3 派生 selector：审核中心的行数据

审核中心的素材列表要合并**两个数据源**（`plazaSubmissions` 和 `world.assets` 里的广场资产），不能只看其中一个。在 `useStore.ts` 里导出一个纯函数（不要写在页面里）：

```ts
/**
 * 审核中心「素材」Tab 的一行。
 *
 * 为什么要专门造这个形状：admin 眼里的一条「素材审核记录」，
 * 在数据里其实可能是两种东西之一——
 *   · 还没过审 / 被驳回的：一条 PlazaSubmission（世界里还没有对应的广场资产）
 *   · 已上架 / 已下架的：一份 scope==='plaza' 的 Asset
 * 种子里的官方素材更特殊：只有 Asset，压根没走过投稿流程。
 * 页面不该关心这些差别，所以在这里把三种情况碾平成同一行。
 */
export interface PlazaReviewRow {
  key: string
  assetId?: string        // 已上架 / 已下架时有
  submissionId?: string   // 走过投稿流程的才有；官方素材没有
  name: string
  cover: string
  category: Category
  submitterName: string   // 无投稿人时显示「官方」
  fromLabel: string       // '团队资产库' / 项目名 / '官方'
  createdAt: number
  status: 'pending' | 'listed' | 'delisted' | 'rejected'
  reason?: string         // 驳回或下架的理由
}

export function selectPlazaReviewRows(state: StoreState): PlazaReviewRow[]
```

**派生规则（写进注释）**：
- `status==='pending'` 和 `'rejected'` 的 submission → 各出一行；
- `status==='approved'` 的 submission → **不单独出行**（它对应的资产已经在 `world.assets` 里，会从下面那条出行，否则会重复）；
- 每一份 `scope==='plaza'` 的 asset → 出一行，`status` 由 `isListed()` 决定（`listed` / `delisted`）；通过 `plazaSubmissions.find(s => s.resultAssetId === asset.id)` 反查投稿人；查不到就是官方素材，投稿人显示「官方」；
- 按 `createdAt` 倒序。

同样给主账号那条线导出 `selectDepositRows(state)`，把现有 `DepositReview` 里内联的过滤逻辑搬出来（申请人是我名下子账号 + 按状态分组），页面只管渲染。

## 7. 广场页过滤 · `src/pages/PlazaPage.tsx`

`plazaAssets` 的过滤链上补一道：

```ts
    () => world.assets.filter((a) => a.scope === 'plaza' && isListed(a) && canSee(world, user, a)),
```

**为什么 `canSee` 已经处理了还要加这一道**（写进注释）：`canSee` 里给了投稿人本人一个口子——让他在别处（比如通知跳转、我的投稿）能看到自己被下架的那份。但广场是**对外货架**，下架的东西不该混在货架里给作者一个人看。所以货架页显式再收一次。
