## 0 · 三条主线

这次改动只做三件事，其余都是它们的衍生：

| # | 主线 | 一句话 |
|---|---|---|
| **A** | **状态机简化** | 删掉 `pending`（待定稿）。只要一份资产里有图，就必然有且只有一张定稿；换定稿只能"换"，不能"取消"。 |
| **B** | **流转下沉到图** | 「存入团队库 / 贡献到素材广场」不再是资产级动作，而是**某一张图**的动作。离开项目库的每一张图都要过一次弹窗、起一个不重复的名字。 |
| **C** | **统一上传弹窗** | 画布保存、库内上传共用一个弹窗：**层 → 类目 → 名称 →（仅项目库）保存方式**。上传目标可以是三层中的任意一层。 |

配套的界面收口（预览比例、参考图第一位、加号入口、文案）随这三条一起落。

### 三条产品判断（读代码的人要先理解这个，否则会改歪）

1. **项目资产库 = 生产工位；团队资产库 / 素材广场 = 网盘。**
   项目库里的一份资产有身份（名字 / 提示词 / 参考图）+ 一堆产物（图片列表）+ 一个对外代表（定稿）。
   团队库和广场里的一份"资产"本质上就是**一张独立的图片**——没有图片列表、没有生成入口、没有定稿概念。

2. **"定稿"只管两件事**：这份资产在项目里的封面、以及它能不能被别的资产选作参考图。
   它**不再兼管"能不能出库"**——出库是单张图自己的事。这就是为什么可以安全地取消「取消定稿」。

3. **唯一的守门规则是名字不重复。** 不做来源循环检测、不做血缘角标、不做批量存入。
   上传弹窗里的名称字段就是这道门，且**只有这一道门**。

## 1 · 数据层 · `src/data/types.ts`

### 1.1 删除 `pending` 状态

```ts
// 改前
export type AssetStatus = 'empty' | 'generating' | 'pending' | 'done' | 'failed'
// 改后
export type AssetStatus = 'empty' | 'generating' | 'done' | 'failed'
//                         空壳      生成中         成品      失败
```

同步重写该类型上方的注释块，新的状态机说明：

```
empty      空壳   —— 图片列表为空、cover 为空。只有名字 / 提示词 / 参考图。
generating 生成中 —— 本次生成在途（demo 用定时器模拟，1.2s 后落地）。
done       成品   —— 图片列表非空，cover 指向其中某一张。
failed     失败

★ 核心不变量（0810）★
   图片列表非空  ⇔  cover 非空，且 cover ∈ 图片列表
   一份资产只要有图，就必然有且只有一张定稿。不存在"有图但没定稿"的中间态。
   换定稿 = 换 cover 指向；删光图 = 降级回 empty。
```

### 1.2 `Asset.cover` / `Asset.candidates` 注释更新

- `cover`：补一句「有图必有定稿，见状态机不变量」。
- `candidates`：把旧注释里"定稿图必定也在池中"保留，补一句"反过来也成立：池非空则 cover 必非空"。

### 1.3 `Asset.referenceImages` 语义收窄

参考图**只存"来源参考"**（素模 / 服装 / 用户手动挂的图）。
资产自己的定稿图**不再写进这个数组**，改为渲染时派生（见 §5.1.4）。


### 1.4 新增：扁平化图片载荷

新增一个类型（放在 `Candidate` 定义下方）：

```ts
/**
 * 扁平化图片载荷（0810）：一张图离开项目库时携带的全部信息。
 *
 * 这是「流转的最小单位是图，不是资产」的数据表达。存入团队库 / 贡献到素材广场，
 * 送出去的都是它——而不是一份带图片列表和参考图的资产。
 *
 * 为什么申请 / 投稿要带快照而不是 assetId：
 *   在途期间源资产可能被改名、删图、甚至整份删掉。带快照，审批那一刻落库的
 *   就是用户当初提交的那张图，不会被上游变动搅乱。
 */
export interface FlatImagePayload {
  url: string          // 这张图
  name: string         // 用户在弹窗里起的名字（去空格后）
  category: Category   // 不允许 'other'
  prompt?: string      // 提示词随图走（离开项目库后只读）
  voice?: Voice        // 仅角色类目；随图走
}
```

### 2.3 `assertDone` → 删除，换成 `assertPayload`

`assertDone` 服务的是"只有成品才能流转"的旧红线。流转下沉到图之后，
"这张图存不存在"由调用方在选图时就保证了，不需要资产级状态校验。

```ts
/** 校验一张图的出库载荷是否合法（0810）。 */
function assertPayload(p: FlatImagePayload, target: '团队库' | '素材广场'): void {
  if (!p.url) throw new AssetRuleError('没有可提交的图片。')
  if (!p.name.trim()) throw new AssetRuleError('请先给这张素材起个名字。')
  if (p.category === 'other') {
    throw new AssetRuleError(
      target === '素材广场'
        ? '「其他」类目不能贡献到素材广场。'
        : '「其他」类目仅存在于项目资产库，不能存入团队库。',
    )
  }
}
```

`assertNotOther` 的职责被并入 `assertPayload`，原函数删除。
**注意**：错误文案里必须保留 `团队库` / `素材广场` 这两个词（现有测试用正则匹配，见 §9）。

`directReuse` / `favorite` / `reuse` 三个**下行**动作仍然是"整份资产拷贝"，
它们的 `assertDone(source, ...)` 调用改为一句更朴素的守卫：

```ts
function assertHasImage(source: Asset, action: string): void {
  if (!source.cover) {
    throw new AssetRuleError(`资产「${source.name}」还没有图片，不能${action}。`)
  }
```

### 2.4 新增 `flattenToLibrary`

这是 B 主线的核心函数：把一张图落成团队库 / 广场里的一份独立素材。

```ts
/**
 * 扁平化落库（0810）：把一张图落成团队库 / 广场里的一份独立素材。
 *
 * 【丢掉】图片列表(candidates) / 参考图(referenceImages,referenceLabels) /
 *         来源(referencedFrom) / 血缘(masterId) / 状态机（永远 done）
 * 【带走】图、名称、类目、提示词、音色（角色）
 *
 * 为什么提示词一定要带走：它是这张图作为"可复用素材"最值钱的部分——
 * 别人复用回项目库时能直接照着重新生成。进广场后随图一起冻结、不可编辑。
 */
export function flattenToLibrary(
  payload: FlatImagePayload,
  target:
    | { scope: 'team'; scopeId: string }
    | { scope: 'plaza'; contributedBy: string },
): Asset {
  return {
    id: makeId('asset'),
    category: payload.category,
    name: payload.name.trim(),
    scope: target.scope,
    scopeId: target.scope === 'team' ? target.scopeId : undefined,
    status: 'done',
    masterId: undefined,          // 它自己就是这一层的母版
    prompt: payload.prompt,
    cover: payload.url,
    candidates: undefined,        // ← 扁平：没有图片列表
    referenceImages: undefined,   // ← 扁平：没有参考图
    referenceLabels: undefined,
    referencedFrom: undefined,
    fields: {},
    tags: [],
    voice: payload.voice ? { ...payload.voice } : undefined,
    contributedBy: target.scope === 'plaza' ? target.contributedBy : undefined,
    shelfStatus: target.scope === 'plaza' ? 'listed' : undefined,
    createdAt: Date.now(),
  }
}
```

### 2.8 新增 `imageBelongsTo`

界面选中一张图送出时，用它挡住"送一张不属于这份资产的图"。

```ts
/** 这个 url 是不是这份资产的图（定稿或图片列表里的任意一张，按去后缀的裸地址比）。 */
export function imageBelongsTo(asset: Asset, url: string): boolean {
  const bare = (u: string) => u.split('?')[0]
  const k = bare(url)
  if (asset.cover && bare(asset.cover) === k) return true
  return (asset.candidates ?? []).some((c) => bare(c.url) === k)
}
```

### 3.1 新增：广场同名检测（按投稿人维度）

与 `libraryHasSameName` / `teamHasSameName` 并列放在文件末尾：

```ts
/**
 * 广场同名检测（0810）：**按投稿人维度**唯一，而不是全网唯一。
 *
 * 为什么不做全网唯一：广场是全网货架，第一个投「西装」的人就会把这个名字占死，
 * 后面所有人再也不能叫「西装」——用户会觉得莫名其妙。所以只保证"你自己不能投两张同名的"，
 * 不同投稿人之间允许重名，展示时靠投稿人区分。
 *
 * 官方素材（无 contributedBy）不参与个人维度校验。
 */
export function plazaHasSameNameBySubmitter(
  assets: Asset[],
  submitterId: string,
  name: string,
  excludeId?: string,
): boolean {
  return assets.some(
    (a) =>
      a.scope === 'plaza' &&
      a.contributedBy === submitterId &&
      a.name === name.trim() &&
      a.id !== excludeId,
  )
}
```

```ts
/** 这个节点还能存到哪几层（0810 · 统一上传弹窗的层选项来源）。 */
export function scopesForNode(node: CanvasNode): Scope[] {
  const all: Scope[] = ['project', 'team', 'plaza']
  // 已经是本项目资产的节点，不给"再存一次项目库"。
```

#### 5.3.4 名称字段：实时重名校验

```ts
const nameError = useMemo(() => {
  const nm = name.trim()
  if (!nm) return null                      // 空不报错，只是按钮 disabled
  if (scope === 'project')
    return libraryHasSameName(allAssets, 'project', projectId, nm)
      ? '该项目已有同名素材，请换个名字' : null
  if (scope === 'team')
    return currentTeamId && libraryHasSameName(allAssets, 'team', currentTeamId, nm)
      ? '团队资产库已有同名素材，请换个名字' : null
  return plazaHasSameNameBySubmitter(allAssets, currentUser.id, nm)
    ? '你已经投过同名的素材，请换个名字' : null
}, [name, scope, projectId, currentTeamId, allAssets, currentUser.id])
```

- `确认添加` 按钮 `disabled = !intent || !!nameError`。

#### 5.3.5 第 ⑤ 段文案表

| 层 | 当前账号 | 文案 |
|---|---|---|
| 项目资产库 | 任意 | 将作为一份新资产存入，可继续编辑提示词与生成 |
| 项目资产库（mode=link） | 任意 | 将加入「{目标资产名}」的图片列表 |
