# 技术规划 · 0811 —— 收口轮

> 承接《技术规划-0810-流转下沉与状态机简化》。0810 的三条主线已落地，本轮只做交互与文案收口，
> **不改任何数据结构、不改流转规则**。唯一的规则级新增是 §1 的「置灰 / 消失」判据。

---

## 1 · 一条新规则：选项置灰，段落消失

这轮反馈里反复出现同一个问题——**系统悄悄拿掉了用户以为存在的选项**（视频保存时分类段整个消失、
团队库目标下「其他」被 filter 掉、音频不给团队库/广场）。用户看不到边界，只看到界面在跳。

统一判据：

| 情况 | 做法 |
|---|---|
| 同一组选项里少一个可选项 | **保留位置 + 置灰 + 一句原因**。用户能学到系统的边界，下次不会再试。 |
| 整个概念不适用 | **整段消失**。不适用的概念不该占用户的注意力。 |

按这条判据，本轮要改的四处：

- 视频 / 文本保存 → 分类段**不再整段消失**，四个视觉类目置灰，「其他」选中（§5.3）
- 团队库 / 广场目标下的「其他」类目 → 从 filter 掉改为**置灰**（§5.4）
- 音频的「团队资产库」「素材广场」两个层瓷砖 → **置灰**（§5.5）
- 「保存方式」段在团队库 / 广场目标下 → **保持整段消失**（这是概念不适用，正确，不动）

置灰态的统一样式：`opacity: .38; cursor: not-allowed; pointer-events: none`，
外层包一层 `title` 属性给原因；同时在该段下方常驻一行 11.5px 灰字说明（不是 hover 才出，
因为置灰项本身就不响应 hover）。

## 5 · 保存弹窗 · `src/components/AssetSaveModal.tsx`

### 5.1 文案清理（3a）

删掉全部解释性副文案，只留标题：

```tsx
// 「保存方式」两块瓷砖：删掉 modeSub
<button className={...}>新建一份</button>
<button className={...}>加到已有素材里</button>
```

| 原文案 | 处理 |
|---|---|
| `新建一份资产` | → `新建一份` |
| `作为一份新的顶层资产存入`（modeSub） | **删除** |
| `加入已有资产的图片列表` | → `加到已有素材里` |
| `选一份同类资产`（modeSub） | **删除**；已选目标时在瓷砖内显示 `→ 阿杰`，未选就什么都不显示 |
| `选择目标{类目}`（popTitle） | → `加到哪一份` |
| `本项目还没有{类目}`（popEmpty） | → `这个项目里还没有可加入的素材` |
| `确认添加` | → `保存` |

### 5.2 ⑤ 结果预期：只在有意外时才出现

当前 `outcome` 恒显示一行字，其中三句是废话（用户刚选了那一层，当然是存进那一层）。
改为**只在会发生用户没预料到的事时才显示**：

```ts
const outcome = (() => {
  if (scope === 'team' && currentUser.role === 'sub') return '提交后由主账号确认'
  if (scope === 'plaza') return '提交后由平台审核'
  return null   // 其余情况不说话
})()
```

渲染处 `{outcome && <div className={styles.outcomeHint}>{outcome}</div>}`。

> 这一行的全部价值在于"告诉用户会发生一件他没预料到的事"。没有意外就闭嘴——
> 这才是去掉程序员味的正确方式，而不是把同样的废话说得更软。

`mode === 'link'` 时的 `将加入「X」的图片列表` 也删掉：瓷砖里已经显示 `→ 阿杰` 了，重复。

### 5.3 视频 / 文本：分类段不再消失（3c）

当前逻辑 `{!soleDest && (分类段)}` —— `soleDest` 时整段消失，用户看不到"为什么没有分类可选"。

改为：分类段**恒渲染**，不可选的用置灰表达。

```tsx
// dests 改为拿"全集"，再逐项判断可选性
const allDests = destinationsForMedia(media)                 // 该媒介理论上的全部去处
const enabledDests = destinationsForScope(media, scope)      // 当前层实际可选的
const isEnabled = (d: Destination) => enabledDests.includes(d)
```

渲染每个 chip 时：

```tsx
<button
  className={`${styles.catChip} ${dest === d ? styles.catChipOn : ''} ${isEnabled(d) ? '' : styles.catChipOff}`}
  disabled={!isEnabled(d)}
  title={isEnabled(d) ? undefined : disabledReason(d)}
  onClick={() => isEnabled(d) && pickDest(d)}
>
  {DEST_LABEL[d]}
</button>
```

**但视频 / 文本的情况特殊**：它们的 `destinationsForMedia` 本来就只返回 `['other']`，
全集里根本没有四个视觉类目。所以要在弹窗里单独给出"视觉类目占位"：

```ts
/** 分类段永远展示的完整货架（按媒介取），不可选的置灰。 */
const CAT_SHELF: Record<Media, Destination[]> = {
  image: ['character', 'prop', 'costume', 'scene', 'other'],
  video: ['character', 'prop', 'costume', 'scene', 'other'],   // 前四个恒置灰
  text:  ['character', 'prop', 'costume', 'scene', 'other'],   // 前四个恒置灰
  audio: ['audio', 'voice'],
}
```

置灰原因文案（`disabledReason`）：

| 场景 | 文案 |
|---|---|
| 视频 / 文本落视觉类目 | `视频只能存进「其他」` / `文本只能存进「其他」` |
| 团队库 / 广场目标下的「其他」 | `「其他」只留在项目里` |
| 团队库 / 广场目标下的「角色音色」 | `音色只在项目里设置` |

段下方常驻说明（替换掉现在那句出现两次的 `创作留存物（分镜 / 视频片段 / 台词）仅归档于本项目，不存入团队库`）：

- 视频：`视频跟着这个项目走，不进团队资产库和素材广场。`
- 文本：`文本跟着这个项目走，不进团队资产库和素材广场。`

其余情况不出这行说明。**原来那句长文案两处都删掉**（`soleDest` 分支一处、tile 内一处）。

### 5.4 「其他」类目：从 filter 改为置灰

`destinationsForScope` 保持不变（它是**逻辑真相**，服务层要用）。
改的是**渲染**：分类段用 `CAT_SHELF[media]` 取全集，用 `destinationsForScope` 判可选性。

### 5.5 分类段的小竖杠删除（3b）

删掉 `styles.catDivider` 那个 `<span>` 及其外层的 `style={{display:'contents'}}` 包装，
`dests.map` 恢复成朴素的一层 map。CSS `.catDivider` 一并删除。

### 5.6 音频：这一期只落项目资产库（4a / 4b）

**层选择段**：音频媒介下，「团队资产库」「素材广场」两个瓷砖**置灰**（不隐藏），
`title` / 段下说明写：`音频暂时只能存在项目里`。

实现落在 `canvasService.scopesForNode` 与弹窗两处：

```ts
// canvasService.ts —— 逻辑真相：音频这一期只落项目库
export function scopesForNode(node: CanvasNode): Scope[] {
  const noProject = node.source?.scope === 'project'
  // 视频 / 文本 / 音频都只能待在项目库（音频：0811，团队库/广场的音频形态尚未定义）
  if (node.media === 'video' || node.media === 'text' || node.media === 'audio') return ['project']
  const all: Scope[] = ['project', 'team', 'plaza']
  return noProject ? all.filter((s) => s !== 'project') : all
}
```

弹窗层选择段要**渲染三个瓷砖**（全集恒为 `['project','team','plaza']`），
用 `allowedScopes` 判可选性，不可选的置灰。即 `allowedScopes` 从"渲染哪几个"降级成"哪几个可点"。

> **为什么团队库也一起置灰，而不是只灰广场：**
>
> 1. 音频作为"可复用素材"的形态还没定义清楚——一段音频到底是**音色**（绑在角色身上的身份锚点）
>    还是**音效 / BGM**（独立素材）？这两者在团队库里的样子完全不同。没想清楚就开口子，
>    开了以后再关比不开更贵。
> 2. 「在团队库里直接绑定角色音色」这条路建议不做，三个具体原因：
>    - 团队库的资产是**扁平的单图**，不是可继续编辑的工位。给它绑音色 = 给网盘文件加可编辑属性，
>      直接违背 0810 刚立起来的心智。
>    - 绑音色是**写团队库**。子账号写团队库要走审批，但绑音色不产生资产、进不了审批队列——
>      要么破坏审批规则，要么为它单开一条审批线，都不值。
>    - **这条路本来就通**：团队库的角色素材通过 `flattenToLibrary` 已经把源角色的音色带走了；
>      真要换音色，正确路径是「复用回项目 → 在项目里改 → 存回团队库」。不需要新口子。

### 5.7 弹窗尺寸稳定（2c）

当前面板宽度固定（`.panel { max-width: 560px }`），**变的是高度**：
`mode === 'link'` 和 `dest === 'voice'` 时 inline 展开一整个列表（那两处 `position:'static'` 的 `.pop`），
面板高度突增；分类段的条件渲染也让高度跳。

三处改动：

```css
/* ① 内容区给一个下限，短态不塌 */
.content { min-height: 340px; }

/* ② 挑目标的列表固定高度可滚，资产多也不会无限长 */
.pickList { max-height: 200px; overflow-y: auto; }
.pickList::-webkit-scrollbar { width: 6px; }
.pickList::-webkit-scrollbar-thumb { background: #2b323c; border-radius: 6px; }
```

③ 把两处 `style={{ position:'static', marginTop:..., boxShadow:'none' }}` 的内联样式
提成一个正式的类 `.pickList`，不要再用内联覆盖 `.pop`。

改完之后，同一个弹窗在「角色 / 道具 / 场景 / 视频 / 音频」之间切换时高度基本不动。
