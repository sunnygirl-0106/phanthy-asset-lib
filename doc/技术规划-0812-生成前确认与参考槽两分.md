# 技术规划 · 0812 —— 生成前确认与参考槽两分

> 承接《技术规划-0811-收口轮》。本轮有**一处数据结构变更**（参考图 → 参考槽），
> 其余是围绕它长出来的交互。核心目标：把「先生成基础素材、再生成角色造型」
> 这条顺序，从**写死的流程规则**降级成**状态流动的自然结果**。

---

## 0 · 这轮到底在改什么

现在 `ProjectAssetLibrary` 里有这么一段：

```ts
// emptyShells：当前类目下"可以生成了"的造型空壳
a.referencedFrom && (a.referenceImages?.length ?? 0) > 0
```

`types.ts` 白纸黑字写着 `referencedFrom` 是「纯展示，不挂任何行为」，但这里拿它当了开关。
于是「有没有参考图」被偷偷升格成「你属于哪一类资产」，产生两个后果：

1. 用户手动新建一份角色，凭什么要选边站？「素模 / 造型」这个二分对他毫无意义。
2. `runDemoGenerate` 必须偷偷给造型「挂上参考图」，才能让它从不可生成变成可生成。
   用户第二步回到详情页，会发现凭空多了两张图——这正是 0811 §1 要治的
   「系统悄悄拿掉/塞给用户东西」。

**本轮的解法：删掉「素模 / 造型」这个概念。** 系统里不再有这两个词。
一份资产就是一份资产，它可能挂了参考槽，也可能没挂；顺序由依赖关系推导，不由分类规定。

## 1 · 一条新规则：参考槽分两种

这是本轮唯一的数据结构变更，也是后面所有交互的地基。

用户手挂的参考图，挂的是**一张图**——项目库右栏那一堆候选图里的某一张，它本来就没有名字。
这与 0810 定的「流转的最小单位是图，不是资产」一脉相承。

而工作流拆剧本时挂的，是**一份资产**——「阿杰·西装造型要参考阿杰这个人」，
此刻阿杰还没出图，槽里除了名字一无所有。

两者语义完全不同，必须在数据上分开：

| | 指向什么 | 显示名字 | 会不会变 | 谁能创建 |
|---|---|---|---|---|
| **图级槽** | 一张具体的图 | **不显示** | 死的，永不变 | **仅用户** |
| **资产级槽** | 一份资产 | **必须显示** | 活的，跟着上游定稿走 | **仅工作流** |

由此直接推出两条本轮反复用到的结论：

- **「参考对象还没出图」这个状态只有工作流能造出来。** 用户手动添加参考图时，
  选择器只列出**已有图**的资产，他没有能力挂一个空的。
- **「第二步给造型挂参考图」这个动作不存在。** 槽从第一步就在，指着阿杰；
  阿杰出图，槽自然就有图了。`runDemoGenerate` 里那段挂参考图的代码整段删除。

## 2 · 资产的六种状态（判据总表）

前 4 个生产类目（`character` / `costume` / `scene` / `prop`）适用。
`audio` 无参考图概念，`other` 不参与生成，两者都不套用本表。

| # | 有无图 | 参考槽 | 上游状态 | 卡片标记 | 批量默认 | 典型来源 |
|---|---|---|---|---|---|---|
| 1 | 没图 | 无 | — | 待生成 | ✅ | 用户新建 / 剧本拆出的素模 |
| 2 | 没图 | 有 | 全部已出图 | 待生成 | ✅ | 用户从库挂图 / 第一批生成完后的造型 |
| 3 | 没图 | 有 | 有的没出图 | 参考图待生成 | ⬜ | **仅工作流**：刚拆完剧本的造型 |
| 4 | 有图 | 无 | — | （无标记） | ⬜ 排最后 | 生成完的素模 / 用户直接上传定稿 |
| 5 | 有图 | 有 | 全部已出图 | （无标记） | ⬜ 排最后 | 生成完的造型 |
| 6 | 有图 | 有 | 有的没出图 | （无标记） | ⬜ 排最后 | 用户点了「知道了，现在生成」/ 上游事后被删图 |

**默认勾选规则收成一句话：**

> 没图，且不等任何人 → 默认勾选。

**这条规则的妙处**：工作流的「两步」不需要任何特殊代码。第一批默认勾的正好是 #1+#2，
剩下的 #3 在第一批生成完之后自动升级成 #2，第二批打开时默认全勾。
**两步是这条规则自己跑出来的结果，不是被规定的。**

### 措辞定稿

- 卡片状态一律用 **「待生成」**，不用「未定稿」。
  0810 已删掉 `pending` 状态、定死「有图必有定稿」，用「未定稿」等于把删掉的中间态请回来。
- 状态 #3 的卡片标记用 **「参考图待生成」**（不是「等参考图」）。

## 3 · 数据层 · `src/data/types.ts`

### 3.1 新增 `AssetRef`

```ts
/**
 * 参考槽（0812）：两种，语义完全不同，不要合并。
 *
 * · image —— 图级槽。用户从素材库挑的一张具体的图。死的，永不变化，不显示名字
 *   （那张图本来就没有名字）。用户只能创建这一种。
 * · asset —— 资产级槽。指向一份资产，图是它当前定稿的派生。活的：上游换定稿这里跟着换，
 *   上游还没出图这里就是空的。只有工作流拆剧本时能创建。
 *
 * 为什么不用「url + 可选 assetId」合成一种：那样"这张图会不会变"就成了隐性知识，
 * 渲染层每次都要重新判断。两种 kind 摆在类型上，读代码的人一眼就知道自己在处理什么。
 */
export type AssetRef =
  | { kind: 'image'; url: string }
  | { kind: 'asset'; assetId: string }
```

### 3.2 `Asset` 上的替换

```ts
export interface Asset {
  // ...
  /** 参考槽（0812）。替代原 referenceImages + referenceLabels 两个下标对齐的平行数组。 */
  references?: AssetRef[]

  // 【删除】referenceImages?: string[]
  // 【删除】referenceLabels?: string[]
}
```

`referencedFrom` **保留但彻底退回纯展示**——只用于卡片/详情上的「参考自 XX」小标签，
全仓库不得再有任何代码用它做判断。（本轮之后 `AssetCard.formLabel` 里那段
「有 referencedFrom 就写角色造型 / 场景变体」也要删，见 §7。）

### 3.3 `fields.lookUrl` 保留

演示脚手架专用（没有生图后端时的出图替身），逻辑不变，接真后端时随 `demoProject.ts` 一并删。

## 4 · 服务层 · `src/services/assetService.ts`

新增一组纯函数，把「槽当前解析成什么」这件事收在一处。所有页面只读这里，不要各自判断。

```ts
/** 一个参考槽在当前 world 下解析成什么。 */
export type ResolvedRef =
  | { state: 'ready';   url: string;  label?: string; assetId?: string }
  | { state: 'pending'; label: string; assetId: string }  // 上游还在，但没出图
  | { state: 'missing'; label: string; assetId: string }  // 上游已被整份删除

/** 解析一份资产的全部参考槽（下标与 references 对齐）。 */
export function resolveRefs(world: World, a: Asset): ResolvedRef[]

/** 还没就位的槽（pending + missing）。空数组 = 全部就位。 */
export function pendingRefs(world: World, a: Asset): ResolvedRef[]

/** 全部就位？没挂槽的资产恒为 true。 */
export function refsReady(world: World, a: Asset): boolean

/** 出图时真正拿得到的参考图 url —— 只有 ready 的槽算数。 */
export function usableRefUrls(world: World, a: Asset): string[]

/** 加参考槽前的环检测：a 参考 target 会不会成环。 */
export function wouldCycle(world: World, aId: string, targetId: string): boolean
```

解析规则：

| 槽 | 解析 |
|---|---|
| `{kind:'image', url}` | 恒 `ready`，`label` 留空 |
| `{kind:'asset', assetId}` · 上游不存在 | `missing`，label 用最后已知名字，取不到就写「已删除」 |
| `{kind:'asset', assetId}` · 上游 `status !== 'done'` | `pending`，label = 上游 `name` |
| `{kind:'asset', assetId}` · 上游 `done` | `ready`，`url` = 上游 `cover`，`label` = 上游 `name` |

**流转时清空**：`flattenToLibrary` / 各拷贝路径原本就把 `referenceImages` / `referenceLabels`
置 `undefined`，改成置 `references: undefined`。理由不变：参考是原始库的生产过程中间物。

## 5 · 状态层 · `src/store/useStore.ts`

### 5.1 `batchGenerate` 重写

现在的实现有三个问题：写死 1 张、瞬时出图、把「跳过」放在结果 toast 里事后告知。

```ts
/**
 * 批量生成（0812 重写）。
 *
 * ① 拓扑排序：参考槽指向本批次内其他资产的，排到后面。被参考的先出图，
 *    下游拿得到真实参考图。检测到环时按原顺序降级处理并 console.warn
 *    （加槽时已挡环，这里只是兜底）。
 * ② 分波落地：同一波的资产同时进 status:'generating'，1200ms 后统一 → done。
 *    波数 = 依赖深度。视觉上「先出角色，再出造型」，和详情页单份生成体感一致。
 * ③ 出图源：usableRefUrls(world, a)[0] → fields.lookUrl（演示替身）→ placeholderUrl。
 *    注意顺序：真实参考图优先于演示替身。
 * ④ countPerAsset 由弹窗传入，默认值仍保持 1（不动，现有测试依赖它）。
 */
batchGenerate: (assetIds: string[], placeholderUrl: string, countPerAsset = 1) => ActionResult
```

**必须补的守卫**：store 用了 `persist`。`generating` 是瞬态，刷新页面后会永久冻在那里。
在 `onRehydrateStorage` 里把所有 `status === 'generating'` 打回 `'empty'`。
（这是本轮之前就存在的隐患，本轮把 generating 用起来之后会变成必现 bug。）

### 5.2 `createShellAsset` 灌兜底提示词

```ts
// 现在：prompt: ''
// 改成：按类目灌 seed.ts 里那套【方括号】模板，与剧本拆出来的资产完全一致。
prompt: PROMPT_BY_CATEGORY[category]
```

### 5.3 参考槽的三个 action 适配

- `removeReferenceImage(assetId, index)` → 重命名 `removeRef(assetId, index)`，按下标从 `references` 移除。
  移除后不再需要同步第二个数组（两分法的直接收益）。
- `addReferenceImages(...)` → 拆成两个语义清晰的：
  ```ts
  /** 用户从素材库挑图（只能挑已出图的资产的某张图）。产出图级槽。 */
  addImageRefs: (assetId: string, urls: string[]) => ActionResult
  /** 工作流拆剧本时建资产级槽。带 wouldCycle 守卫。 */
  addAssetRefs: (assetId: string, targetIds: string[]) => ActionResult
  ```
- 新增标记：资产被用户手动改过参考槽后打 `fields.refsTouched = true`，
  工作流不再往里塞任何东西（**系统只填空位，不覆盖用户的决定**）。

## 6 · 新组件 · `src/components/BatchGenerateModal.tsx`

三个入口统一走这一个弹窗，不再有任何「点了就直接出图」的路径：

| 入口 | 位置 | 列表范围 |
|---|---|---|
| 一键生成全部资产 | 工具条（新增，主 CTA） | 本项目**全部**没图的资产，跨类目 |
| 批量生成（N） | 批量模式工具条（已有） | 勾中的那些 |

而且它按类目切分，和「资产生成是一次把基础素材全出完」的语义打架。

### 6.2 分组与排序

按类目分组（角色 → 服装 → 场景 → 道具），组内按 §2 表的顺序：
`#1/#2`（默认勾）→ `#3`（默认不勾）→ 有图的排全局最后，单独一个「已生成」分区。

### 6.3 参考 pill 三态

**这是本弹窗的信息核心**，它替代了所有说教文案——用户看一眼就知道为什么某行没勾。

| 槽 | 渲染 |
|---|---|
| 图级槽（`kind:'image'`） | 纯缩略图方块，**不带任何文字**。用户自己挑的图，他知道那是什么 |
| 资产级 · ready | pill：缩略图 + 资产名 |
| 资产级 · pending | pill 整颗灰化：灰方块 + 资产名 + `·待生成` |
| 资产级 · missing | pill 灰化 + 资产名 + `·已删除`，鼠标可移除 |

没有参考槽的行，整个「参考：」区**不渲染**（不占位）。

### 6.4 文案（定稿，直接抄）

**顶部提示条**（仅当列表里存在 #3 状态的资产）：

> 本次有 **N 份**资产要参考本批次里其他资产的成品图，**已默认不勾选**。
> 建议先生成被参考的资产、确认满意后再生成它们，形象更稳定。需要一次生成完，勾上即可。

**二次确认 · 上游也在本批次里**（用户勾上了 #3，且它的上游也被勾中）：

> **有 N 份资产要参考本批次内的资产**
>
> 系统会先生成被参考的资产，再生成它们，**参考得上**。但你将没有机会在它们出图前
> 先看一眼、换张定稿或改改提示词——一批下来全部既成事实。
>
> 　　要参考同批资产的：阿杰·西装造型 · 苏可·睡衣造型
> 　　被参考的（本批次内）：阿杰 · 西装 · 苏可 · 睡衣
>
> `[ 返回调整 ]　[ 知道了，一起生成 ]`

**二次确认 · 上游不在本批次里**（详情页单份生成走的也是这一套）：

> **这次生成不会参考到这 N 份资产**
>
> 它们还没有图，模型拿不到，**只能按提示词自由发挥**。参考槽会留着——
> 等它们出图后再生成一次，就参考得上了。
>
> 　　这次参考不到的：阿杰 · 西装
>
> `[ 返回等一等 ]　[ 知道了，现在生成 ]`

> **文案原则**：确定的事用确定的语气。「这次不会参考到」是事实，不是「可能对不上」这种
> 含糊的风险提示。按钮写「知道了，现在生成」而不是「仍然生成」——用户按下去的是
> 「我知道会发生什么」，不是「我无视警告」。

### 6.5 引导条（替代原 Tab 行按钮）

页面顶部常驻一条（不是 toast，toast 会跑掉），判据是**通用的**：

> N 份资产的参考图已全部就位　`[ 生成这 N 份 ]`

**判据**：`status === 'empty'` 且 `references?.length > 0` 且 `refsReady()`（即状态 #2）。
用户手动新建、自己从素材库挂了参考图的资产同样会被捞出来——这是对的，它陈述的是事实。

**关键区分**：引导条属于**资产库**，只陈述状态、不提「下一步」。
工作流的「第三步：生成角色造型」属于**工作流**，它只认自己拆出来的那批 id，
用户手建的资产永远不进那个进度条——不是被判据排除，是它压根不属于那条流程。

> **一句话：流程负责催，资产负责说。** 之前想用一条横幅同时干这两件事，所以怎么写都别扭。

### 6.6 相对 Figma `node 80:9` 的 5 处修改

1. **加顶部提示条** —— 原设计只有灰 pill 上一行小字，用户看到「已选 3/7」不知道为什么
2. **提示词改为可编辑 textarea** —— 确认的实质就是确认提示词；改完 `onBlur` 走 `setPrompt`
3. **补星钻** —— 底部加「⚡ N 星钻」，`已选数 × 每份张数 × COST_PER_IMAGE`
4. **补「已生成」分区** —— 原设计 7 份全是空壳，没有 #4/#5/#6 的位置
5. **图级槽不显示名字** —— 原设计所有 pill 都带名字，等于假设参考都是资产级的
6. **去掉行尾拖拽手柄（⋮⋮）** —— 手动排序会和拓扑排序打架，语义冲突

## 7 · 卡片 · `src/components/AssetCard.tsx`

### 7.1 空壳卡片：名字进框内

```
┌──────────────┐
│              │
│   阿杰·西装造型  │   ← 名字（居中，主色）
│   参考图待生成    │   ← 状态小字（灰 / 琥珀）
│              │
└──────────────┘
```

**所有没图的卡片一视同仁**，不区分工作流拆的还是用户建的——同一种状态不能有两种长相。
下方不再重复名字。有图的卡片保持现状（满幅封面 + 底部浮层名字）。

现在的实现是「有提示词就把提示词当封面预览」——那段删掉。提示词模板全是方括号占位，

## 8 · 详情页 · `src/components/AssetDetail.tsx`

### 8.1 参考图区三态

按 §6.3 同一套规则渲染，尺寸放大到 78×98。资产级槽的名字**常驻**（它没有图可看，
名字是唯一标识）；图级槽不显示任何文字（保持 0811「去掉常驻标签」的决定）。

「当前定稿」自参考槽的派生逻辑不变（0810），仍然不写进 `references`。

### 8.2 有 pending 槽时的警示行

放在参数区下方、生成按钮上方：

> ◷ **阿杰、西装** 还没出图，**这次生成不会参考到它们**，模型只能按提示词自由发挥。
> 槽位会留着，等它们出图后再生成就参考得上。

### 8.3 生成按钮：软拦截

**不禁用。** 点击时若 `pendingRefs().length > 0`，弹 §6.4 的第二种二次确认，确认后照常生成。

**为什么不硬拦**：参考槽是空的，那张图根本不存在，模型拿不到——这次生成只是「少参考一张」，
不是错误操作。真正的问题是用户以为自己参考上了，那用一句准确的话就能解决，不必动用拒绝权。

**而且硬拦有死局**：用户挂的上游被同事删了、或从广场复用的资产被下架，这份资产会永久卡死，
除非他自己想到去删参考槽——但界面从没告诉过他可以删。
**一条规则如果存在无法自愈的死局，它就不该是硬规则。**

### 8.4 槽位保留，不移除

生成后 pending 槽照留（等上游出图，下次生成自动就参考得上）。
这与仓库既有的自参考槽 ✕（「本次生成不以当前定稿为底」，只关这一次、不动数据）是同一个模式。

用户主动点槽上的 ✕ 才是永久移除，移除后这份资产从 #3 落回 #1，立刻可生成，
并打 `fields.refsTouched = true`。

## 9 · 参考图选择器（用户添加参考图）

**只列出 `status === 'done'` 的资产的图。** 用户没有能力创建 pending 槽——
这是 §1 那条「参考对象没图只有工作流能造」的落点，务必在选择器层面就挡掉，
而不是挂上之后再提示。

加槽时跑 `wouldCycle()`，成环则拒绝并提示「不能互相参考」。

## 10 · 明确不做

- **图级槽 ↔ 资产级槽互转**（「我就要现在这张，别跟着阿杰变」）——过度设计，本期留白
- **参考深度限制**——不限制，只禁止成环
- **手动调整生成顺序**——由拓扑排序决定，不给用户入口
- **音频 / 「其他」的参考槽**——这两个类目不适用 §2 状态表

## 附 · 一句话总结

**删掉「素模 / 造型」这个概念，把顺序交给依赖关系。**
工作流仍然三步走，但那三步不再是规则，而是状态流动的结果——
所以工作流一步没改，用户那边一条限制也没多。
