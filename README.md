# 资产库 Demo · 逻辑内核（当前阶段）

这是 PhantyMovie「资产库 & 素材广场」Demo 的仓库。
我们采用**逻辑内核优先**的路线：先把产品最重、最容易错的那部分——
**权限规则**和**资产流转规则**——写成干净、可测试的纯函数（这就是"没有服务器的后端"），
再在它上面搭界面。

> 为什么这么做：这个产品的难点全在"逻辑"（谁能看、往哪流、副本怎么算），而不在界面。
> 把逻辑先钉死在 service 层，改起来最便宜；将来接真后端时，这一层几乎原样搬到服务器端。

---

## 怎么跑起来

需要本机装了 Node（建议 18 以上）。在仓库根目录依次执行：

```bash
npm install       # 第一次：装依赖
npm test          # ★ 看逻辑内核的全部规则断言（应全部通过，28 条）
npm run dev       # 启动开发服务器，浏览器打开它给的地址，看到"逻辑内核体检台"
```

其它命令：

```bash
npm run typecheck # 只做类型检查，不运行
npm run build     # 生产构建（会先做类型检查再打包）
```

**建议先跑 `npm test`。** 那些绿色的勾，就是"每一条产品规则都成立"的证明。
想读规则本身，直接看 `src/tests/logic-core.test.ts`——每个 `it("……")` 里的中文就是一条规则。

## 代码结构（按"数据 → 服务 → 界面"分层）

```
src/
  data/                  【数据层】数据长什么样
    types.ts               所有数据结构的 TS 类型 = 活文档（先读它）
    seed.ts                一小组假数据：账号/团队/项目/资产
  services/              【服务层】模拟后端：规则都在这里，纯函数
    permission.ts          权限：canSee / canFavorite / depositMode …（对照产品的权限矩阵）
    assetService.ts        流转：直接复用 / 收藏 / 复用 / 沉淀 + 跟随/断链
  tests/
    logic-core.test.ts     用断言证明上面所有规则成立
  App.tsx                【界面层·占位】一个朴素的"体检台"，看逻辑在浏览器里跑
  main.tsx               React 入口
```

**推荐阅读顺序**：`types.ts` → `permission.ts` → `assetService.ts` → `logic-core.test.ts`。
读完这四个文件，你就掌握了整个资产库的后端逻辑。
